## Deliberate differences from the reference repository

Three places where copying the reference structure would have been wrong for
this product:

1. **Pains are marked `(H)`.** The reference repo's P1–P3 came from real
   interviews. YummyNaKha! is at problem-validation stage, so P1–P4 are
   hypotheses drawn from the Charter and the Brief. Every spec, backlog row, and
   audit tool now distinguishes a hypothesis from an evidenced pain, and
   `/audit-backlog` reports the unvalidated ones. Nothing is quoted as if a user
   said it.

2. **A safety rule sits above the legal rules.** The reference product's worst
   failure is a bad recipe. This product's worst failure is telling someone with
   a peanut allergy that a dish is fine. `CLAUDE.md`, both audit skills, the
   design-writer agent, and the prototype now carry fixed permitted wording and
   an automated copy scan (NFR6) that fails a build on the word "safe".

3. **The architecture diagram separates the Decision Core from the AI
   gateway.** The Brief explicitly warns against being an AI API wrapper, so the
   rule engine, uncertainty logic, and ranking are shown as team-built
   components that make no AI call. That separation is also what makes NFR5's
   100% recall testable.
